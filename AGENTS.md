## Trellis Workflow

Работаем через Trellis. Перед любой задачей — создай Trellis-задачу
через `trellis_task_create`. Не начинай писать код без задачи.
Субагентов ИСПОЛЬЗОВАТЬ ЗАПРЕЩЕНО.

### Маршруты

- **Feature** (`feat-MM-DD-name`): prd → design → design-review → impl → review → check
- **Issue** (`issue-MM-DD-name`): report → analyze → fix → fix-note
- **Refactor** (`refactor-MM-DD-name`): scan → design → apply → done

### Правила

1. **Не перескакивай этапы.** Нельзя перейти к `impl`, пока не закрыт `design-review`.
2. **На этапах планирования (`prd`, `design`, `scan`, `report`) — не пиши код.**
   Только документы через `trellis_artifact_update`.
3. **Каждый шаг закрывается через `trellis_task_update` с доказательством:**
   - для `verification: 'ai'` — запусти тесты, запиши `verified: true` и `verificationNotes`.
   - для `verification: 'human'` — жди моего подтверждения.
4. **Перед закрытием задачи** — убедись, что все шаги `completed`, Git чистый.
5. **Если задача простая** (одна правка, один файл) — скажи мне, я разрешу `no-trellis`.

### Что делать на каждом этапе

- `prd` — требования: что делаем, зачем, критерии приёмки.
- `design` — как делаем: файлы, компоненты, API, схема данных.
- `design-review` — проверка дизайна на дыры.
- `impl` — код. Только здесь можно писать.
- `review` — ревью кода.
- `check` — финальная проверка: тесты, скриншоты, API-статусы.

### Playwright-проверка (обязательна на этапе `check` для UI-фич)

Ты ОБЯЗАН лично пройти Happy Path через Playwright MCP. Не «посмотреть код».
Не «подумать». Открыть браузер и потыкать.

**Что проверить для каждой UI-фичи:**

1. Открыть страницу. Пустая или с ошибкой → **СТОП, баг.**
2. `browser_console_messages` — есть красные ошибки → **СТОП, баг.**
3. `browser_network_requests` — есть 4xx/5xx → **СТОП, баг.**
4. Пройти Happy Path руками: кликнуть каждую кнопку, заполнить каждую форму,
   сохранить. После каждого действия — снова snapshot + console.
5. Проверить состояния: loading / error / empty / disabled.
6. Скриншоты: 1440px и 375px.

**Доказательства в `trellis_task_update`:**
- список пройденных шагов с результатом каждого
- пустой консоль-лог (без error)
- Network: все нужные эндпоинты, все 2xx
- оба скриншота
- `verified: true` + `verificationNotes` со всем этим

**Без любого из этих пунктов `completed` не ставится.**

**Если баг:**
1. Зафиксировать: шаг, элемент, консоль, запрос.
2. Вернуться в `impl`.
3. Починить.
4. Прогнать Playwright с шага 1 заново.
5. 3 попытки не помогли → СТОП, пиши мне с отчётом.

**HITL на `check`:** даже если агент всё проверил, финальный `completed`
ставится только после моего `verifiedBy: 'human'`.

**Запрещено:**
- Закрывать `check` без скриншотов.
- Закрывать `check` с ошибками в консоли или 4xx/5xx в Network.
- Писать «проверено визуально» без скриншота.
- Писать «тест прошёл» без логов.
- Писать «я думаю, что работает».
