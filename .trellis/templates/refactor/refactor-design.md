## Декларация эквивалентности поведения
Рефакторинг **не меняет** внешне наблюдаемое поведение (результат UI, протоколы, семантика кэша, семантика ошибок). Если меняет — перевести в feat/issue.

## Шаги выполнения
- Список шагов живёт только в `task.json.steps` (вносится на планировании через `trellis_task_update`, параметр `steps`);
  у каждого шага указываются `acceptance` (измеримые критерии) и `verification`:
  - `verification: 'ai'` — шаг проверяет модель/автоматика (`verified: true` + `verifiedBy: 'ai'`);
  - `verification: 'human'` — шаг закрывается только явным подтверждением пользователя (`verifiedBy: 'human'`), это человеческий барьер.
- Команды проверки фиксируются по качественным гейтам проекта (`.trellis/spec/`); для чисто документных правок укажите, что прогон не требуется.
